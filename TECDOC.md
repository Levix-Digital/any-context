# AnyContext — Technical Documentation

Entry point to the architecture of AnyContext (`actx`). This index is maintained with the
`architecture-docs` skill: the sections between `architecture-docs` markers are
generated by `build_index.py`; the rest is written by hand. User documentation is in
[README.md](README.md); release history is in the GitHub releases of
`Levix-Digital/any-context-releases`.

## System Overview

AnyContext is a local-first contextual AI agent written in Rust. A user registers folders and web
sources in a **workspace**; AnyContext indexes them into a local vector database and a lexical
index, and answers questions grounded in those documents through a terminal interface or one-shot
CLI calls. Everything except the language model call runs on the user's machine.

The code is a Cargo workspace of six crates:

| Crate | Role |
|---|---|
| `crates/any-context-core-rs` | Core domain: ingestion and sync, chunkers, retrieval, storage, command engine, model catalog, hardware profiling, theme tokens. |
| `crates/actx-agent` | Agent runtime: routing, one-hop RAG, ReAct loop, Deep Search, tools, session memory. |
| `crates/actx-lm` | Language model providers (OpenAI-compatible, Anthropic, Gemini, mock). |
| `crates/actx-onnx` | Optional local inference on ONNX Runtime (cross-encoder re-ranker). |
| `crates/actx-cli` | The `actx` binary: CLI, terminal UI and agent assembly. |
| `crates/actx-installer` | Installer, updater and model provisioning. |

```mermaid
flowchart LR
    U[User] --> CLI[actx CLI / TUI]
    CLI --> CMD[Command Engine]
    CLI --> AG[Agent Runtime]
    CMD -->|spawns| W[Sync worker]
    W --> ING[Ingestion and chunkers]
    ING --> LDB[(LanceDB vectors)]
    ING --> BM[(BM25 index)]
    AG --> RET[Retrieval Pipeline]
    RET --> LDB
    RET --> BM
    RET --> RR[ONNX cross-encoder]
    AG --> LM[LM providers]
    LM --> API[Cloud or local model APIs]
    CMD & AG & ING --> SQL[(SQLite settings.db)]
    INS[Installer and Updater] --> REL[GitHub releases]
```

A question flows from the CLI or TUI to the agent. The agent routes it: fast questions get one
hybrid search (dense vectors, BM25, Reciprocal Rank Fusion and cross-encoder re-ranking) and a
single model call; complex questions go through Deep Search, which decomposes, searches in batches
and reflects before answering. Slash commands go to the UI-agnostic command engine, which changes
workspace settings in SQLite and starts background sync workers. State lives in two local stores:
LanceDB (chunks and embeddings, with the BM25 file next to it) and SQLite `settings.db`
(workspaces, sources, settings, sync telemetry and conversation memory).

## How to Update This Documentation

- **A subsystem changed** (behavior, structure, data): edit its page in `docs/architecture/` in place, replacing outdated text.
- **A decision with alternatives and trade-offs**: create an ADR with `new_adr.py` and link it from the subsystem page.
- **A decision that reverses or corrects another**: create a new ADR with `--supersedes` or `--amends`; never rewrite an accepted ADR.
- **A feature was removed**: remove it from the subsystem page; its ADRs stay as history.
- **A release**: nothing here; release notes live in the GitHub releases.
- Run `check_docs.py` before committing.
