     `cmd /c 'call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1 && <command>'`

   - `tree-sitter = "0.24"`
   - `tree-sitter-python = "0.23"`
   - `tree-sitter-typescript = "0.23.2"`
   - `tree-sitter-java = "0.23.5"`
   - `tree-sitter-c-sharp = "=0.23.1"`

   - `tree-sitter-rust = "0.23.2"`
   - `tree-sitter-c = "0.23.4"`

## 🧭 Full Specification for the Next Session: Milestone 3

### Goal: Universal, Agnostic `StructuredDataChunker` in Rust (`crates/any-context-core-rs`)

AnyContext is a global, agnostic platform. Therefore the structured data parser **must NOT contain hardcoded rules or schemas of any specific country or domain** (neither Brazilian tax, nor American finance, nor European accounting).

The parser must be **100% generic, universal and content-agnostic**, handling **XML, JSON and YAML** with the same structural elegance, preserving node hierarchies, key paths and syntactic integrity.

#### 1. Universal XML Parser (`xml.rs` through `quick-xml` in Rust):
- **Total Agnosticism**: processes any XML file (`.xml`, `.xsd`, `.rss`, `.atom`, `.svg`, `.plist`, etc.), whether a `pom.xml`, an application manifest, an RSS feed, a configuration file or a SOAP payload.
- **Tag Path Breadcrumbs**:
  - Keeps an active stack of the ancestor nodes:
    `// Context: pom.xml > project > dependencies > dependency[2] [lines 80-95]`
    `// Context: feed.xml > rss > channel > item[10] [lines 150-180]`
    `// Context: config.xml > server > security > realm [lines 25-45]`
- **Attribute Preservation**: attributes of the parent tag/node are kept in the context (e.g. `<dependency scope="test">`).
- **Slicing at Element Boundaries**:
  - Atomic elements or whole subtrees are kept intact.
  - Never splits in the middle of opening/closing tags, attributes or text/CDATA blocks.
  - Repetitive subtrees (records) form natural, cohesive semantic chunks.

#### 2. Universal JSON and YAML Parser (`json.rs` and `yaml.rs` through `serde_json` and `serde_yaml`):
- **Keypath Breadcrumbs**:
  - Dynamic tracking of keys and array indexes:
    `// Context: config.json > database > connection_pool > max_connections`
    `// Context: deploy.yaml > spec > template > spec > containers[0] > env[2]`
- **Slicing that Respects Objects and Lists**:
  - Objects and dictionaries are partitioned at logical boundaries without splitting key-value pairs.
  - Long arrays of homogeneous records are sliced into contiguous blocks of items, propagating the keypath.
