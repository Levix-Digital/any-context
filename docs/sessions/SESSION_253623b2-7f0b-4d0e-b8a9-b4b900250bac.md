## 🔒 Decisões Técnicas Críticas & Armadilhas Superadas

1. **Virtualenv Obrigatório**:
   - Nunca instalar no Python global. Usar exclusivamente `.venv\Scripts\python.exe` e `.venv\Scripts\pip.exe`.
2. **MSVC para Compilação Rust/C no Windows**:
   - Sempre executar comandos de build/check envolvendo gramáticas C sob:
     `cmd /c 'call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1 && <comando>'`
3. **Versões Específicas de Tree-sitter para ABI 14**:
   - `tree-sitter = "0.24"`
   - `tree-sitter-python = "0.23"`
   - `tree-sitter-typescript = "0.23.2"`
   - `tree-sitter-java = "0.23.5"`
   - `tree-sitter-c-sharp = "=0.23.1"`
   - `tree-sitter-go = "0.23.4"` (não usar 0.25.0 pois requer ABI 15)
   - `tree-sitter-rust = "0.23.2"`
   - `tree-sitter-c = "0.23.4"`
   - `tree-sitter-cpp = "0.23.4"`
4. **Estrutura de `ChunkPayload` em Rust**:
   - Não tentar passar `token_count` ou `char_count` nos literais de `ChunkPayload` em Rust (não pertencem ao struct).
5. **Inicialização do PyO3 em Testes Nativos**:
   - Chamar `pyo3::prepare_freethreaded_python();` antes de instanciar `IngestionRouter` em testes unitários Rust para evitar falha no intérprete.
6. **Fatiamento de Nós Tree-sitter**:
   - Usar `&content[node.start_byte()..node.end_byte()]`. Nunca usar `node.utf8_text(b"")`.
7. **Padrão Acumulativo de Testes Manuais**:
   - `tests/MANUAL_TESTS.md` nunca deve ter cenários antigos apagados ou truncados. Sempre prepender o cenário da nova versão e re-numerar os subsequentes.
8. **Isolamento de Documentos de Teste**:
   - Manter os arquivos de teste locais em `tests/documents/` protegidos no `.gitignore` via `/tests/documents/`.

### Objetivo: `StructuredDataChunker` Nativo em Rust (`crates/any-context-core-rs`)
1. **XMLs Fiscais Brasileiros**:
   - Suporte a:
     - **NF-e** (Nota Fiscal Eletrônica - Modelo 55)
     - **NFC-e** (Nota Fiscal de Consumidor Eletrônica - Modelo 65)
     - **CT-e** (Conhecimento de Transporte Eletrônico - Modelo 57)
     - **MDF-e** (Manifesto Eletrônico de Documentos Fiscais)
   - Parser rápido via `quick-xml`:
     - **Metadados do Cabeçalho**: Chave de acesso de 44 dígitos (`chNFe`), número da nota, série, data/hora de emissão e protocolo de autorização.
     - **Emitente & Destinatário**: Razão social, CNPJ/CPF, Inscrição Estadual, endereço completo (UF, Município, Bairro, CEP).
     - **Totais & Tributação**: Base de cálculo de ICMS, valor do ICMS, ICMS-ST, PIS, COFINS, IPI, valor dos produtos, valor do frete, desconto e valor total da nota.
     - **Tabela de Itens (`det`)**: Número do item, código do produto, descrição comercial (`xProd`), código NCM, código CFOP, unidade comercial, quantidade, valor unitário, valor total do produto e alíquotas tributárias.
     - **Breadcrumbs Contextuais Ricos**:
       `// Context: NFe_352409...xml > NF-e 000.123.456 Série 1 > Emitente: Empresa XYZ [CNPJ: 12.345.678/0001-90]`
       `// Context: NFe_352409...xml > NF-e 000.123.456 Série 1 > Item 1: Parafuso Sextavado [NCM: 73181500 / CFOP: 5102]`
2. **Arquivos JSON e YAML de Configuração**:
   - Parser via `serde_json` e `serde_yaml`.
   - Mapeamento hierárquico de chaves (`keypaths`):
     `// Context: appsettings.json > ConnectionStrings > DefaultConnection`
     `// Context: kubernetes.yaml > spec > template > spec > containers[0] > env`
   - Divisão sem quebrar objetos atômicos ou arrays extensos.
